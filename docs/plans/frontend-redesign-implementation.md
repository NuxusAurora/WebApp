## 解耦约定

Workspace 拥有登录用户与顶层导航；Account/Profile 拥有各自表单状态；CourseSpace 拥有课程查询、选中课程、文件及写操作。API helper 与同源代理保持现有协议，设计组件只消费显式数据与回调，不导入后端模型、不新增全局事件总线。必要时将现有课程状态提取为局部 hook，展示层不能穿透其内部可变状态。

样式使用统一 token 与有范围的组件类，不以广泛元素选择器覆盖系统状态或嵌套表单。异步请求卸载后不写状态；保留 Cookie、请求头、分页和所有错误处理契约。表单、导航和对话框支持键盘、焦点及窄屏。验证覆盖课程新建/选择/修改/删除确认、文件操作、登录与账户表单，并复查依赖与状态所有权。

## 流程

1. 用 impeccable 完成产品事实、方向抽选与用户确认；Taste 贡献布局、字阶与整体一致性，Operate 规则优先于宣传页模板。
2. 记录 surface direction contract，重建应用布局、课程/资料组件、账户表单及状态页；不改业务接口。
3. 类型检查、相关回归测试和生产构建；桌面、手机和实际内嵌浏览器宽度批量检查真实渲染与操作。
4. 运行 impeccable detect，一次修正机械问题；按用户默认主代理规则完成审查与设计文档，不启用全局 hook 或子代理。
5. 更新交接；验证后本地提交、按队列合入 master，更新本地预览，清理独立输出与 worktree；不推送本轮新提交。
