# 从目录开始的自主检索与逐点学习

2026-11-09 用户决策。本文件记录目标流程和实施顺序，尚未实现；现有能力以HANDOFF中的实际验收为准。它更新mainbook第4.4/4.7/4.8、6.1–6.3及Phase4–7的接入顺序，不改写既有历史。

## 产品目标

用户提供课程目录后，平台按小节标题主动上网查找、核对内容，拆成可独立学习的知识点。学习时一次呈现一个知识点，整节学习完成后出题验证。教材正文上传和粘贴均不是必需步骤；优先完善这条路径，完整依赖图谱不阻挡进入学习。

## 学习者流程

1. 确认目录后选择小节。平台结合学科、教材名称、章节和相邻小节标题确定检索范围，避免同名概念串科或扩展到整章。
2. 平台检索公开资料并读取相关正文，以大学公开课程、教材配套资料、学术机构及权威文档为优先来源。搜索摘要只用于定位；未读取或无法支持结论的页面不能被标成已核对。来源存在分歧时保留差异，不把模型记忆包装成检索结果。
3. 模型依据可追溯资料整理本节知识清单，给出定义、学习目标、必要先修、顺序和掌握标准。知识点粒度足以独立解释和评估，避免把整节当一点或无限细分。提供简洁清单和一次小节级确认，保留修改入口，不要求用户逐点填写字段或替平台查资料。
4. 用户开始本节，界面聚焦当前一个知识点：概念讲解、例子或推导、答疑；用户选择继续后推进下一点。支持返回、暂停和刷新续学。不把打开内容、点击下一点或读完讲解等同掌握。
5. 本节知识点均完成学习流程后生成小节测验，覆盖本节清单；必要时用综合题考查多个点。单点过程中不强制每点都完成一套考试。题量、难度及讲解深度沿用课程三档学习目标，具体题量随覆盖需求确定，不预设固定分数线。
6. 用户答题后获得逐题反馈及知识点覆盖/薄弱项，对薄弱点回看讲解并可重新测验。保留每次作答，不用新测验覆盖历史。评估提供掌握建议，MASTERED仍由既有显式确认规则控制。

## 低操作量与失败行为

- 学习者只需选小节、开始学习、提问或继续、提交节末答案。搜索服务和模型由平台或账户既有配置提供，不要求每次选模型、写检索词或上传正文。
- 不将所有章节提前深度检索；以当前小节按需整理，保留结果和来源时间，避免重复查询。内容或结构变化不能悄悄覆盖已有学习进度。
- 搜索失败、资料不足或来源冲突时平台进行有界补查；仍不足则显示简短可重试状态，保留旧内容。新生成内容不得假称完成联网核对，不伪造引用；可展示有支持的部分，未核实项不混入已确认学习清单。
- 本节学习进度与知识掌握状态分开保存；测验前锁定本节知识清单版本，避免学习中重新生成改变考试范围。

## 现状与接入缺口

现有knowledge路由将目录/课程信息交给Gateway生成草稿，尚无公开资料检索、网页内容读取、逐点教学或节末测验。Gateway只实现OpenAI兼容chat/completions，tool_calling能力标记不代表已经能联网。当前配置没有搜索服务端点或凭据；会话中的浏览工具不能直接充当部署应用的后台依赖。

检索接入须先验证一个可由应用后端持续调用的搜索来源，再实现适配器。它可由现有模型服务的已验证联网能力或独立搜索服务提供；不在缺乏证据时假定可用，不自行订购收费服务、伪造默认密钥或将某个公共搜索网页的脆弱抓取当成稳定API。此处保留服务选型为实施前置项，用户无需为学习过程手动搜索。

## 解耦约定

- research领域拥有查询、来源记录、网页内容提取及证据关联，提供可替换SearchProvider和受限内容读取入口。返回标题、URL、来源、获取时间、正文片段和证据ID；没有内容或来源不足时返回明确状态。外部网页是数据，不能作为模型或系统指令。
- knowledge领域继续拥有草稿、正式知识点和版本确认。研究结果通过明确快照传入生成流程；模型输出使用证据ID，平台校验引用确实来自本次研究且支持对应知识点。Gateway保持协议适配和调用审计，不查询课程、不修改领域表。
- learning领域拥有小节学习会话、当前知识点、推进位置和学习清单版本；每次只加载当前点、必要先修、相关证据和本会话历史，不混入其他会话全文。
- assessment领域拥有小节测验、题目与知识点映射、答案、评估和重测历史。出题输入是本节已学习且已确认的正式ID快照，服务端检查覆盖、范围和答案完整性；标准答案不在提交前暴露。学习进度及掌握状态经各自命令更新，不由模型直接写入。
- 前端仅提交选节、开始、继续、答题等命令及显示快照；保存恢复、版本冲突和权限由服务端负责。保持已有草稿、正式ID、课程所有权、学习目标和历史兼容，不引入跨账户缓存。
- 网络检索和模型调用期间不持有课程事务锁。完成后重验所有权/基线；过期或失败保留旧内容。查询、网页读取、生成和教学都有时间/大小/重试限制及取消归属；停止或切节后不迟到覆盖另一个小节。网页读取禁止内网/本机/云元数据地址，逐跳验证重定向，不转发模型密钥或会话Cookie。

## 实施顺序与验收

1. **标题检索与有据知识点。** 验证后端搜索接入，落地research来源/证据存储及适配器，接入已有knowledge生成；保留用户修改、显式确认与ID匹配。真实案例须能从标题检索到相关正文，逐项追到来源；覆盖缺失正文、分歧、越界引用、失败/取消和旧草稿保留。不能只测“Prompt写了联网”或用fixture证明真实检索质量。
2. **当前小节逐点学习。** 新增学习会话和版本化难度策略，按知识清单逐点讲解/答疑/推进并恢复进度；保留多会话隔离。验收下一点/上一点、刷新/退出后恢复、切节取消、三档目标效果、学完不自动掌握。
3. **小节测验闭环。** 节末覆盖出题、作答、评估、薄弱点回访及重测；每题关联真实正式ID，可综合多个点。验收覆盖遗漏、超纲、答案泄露、重复提交/评估幂等、评估失败保留答案、版本变化、历史追溯和掌握确认边界。
4. **复查与本地交付。** 对每一阶段做功能测试和实际浏览器/真实来源或模型验收；逐阶段复查上述职责、依赖及取消路径，解耦结论与功能测试分开报告。当前仅完成前置约定，不声称功能或后置解耦已通过。不推送或更新云端，除非另获授权。
