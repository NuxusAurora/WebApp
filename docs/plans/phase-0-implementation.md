# Phase 0 实施与验收

2026-11-08 用户授权当前主代理完整接管 A/B/C，复用 codex/phase0-c-infra 工作区与既有依赖层，不等待三人交叉评审。不实现 Phase 1 的登录、课程和上传业务。

## 解耦约定

- 浏览器只请求 Next.js 同源 health/ready。服务端代理读取独立后端配置，超时有限，不缓存，不暴露上游连接信息；UI 只消费成功/失败快照。
- FastAPI 通过 lifespan 拥有数据库引擎、Redis 客户端并关闭；health 无依赖；ready 并行检查、每项有限超时，失败仅返回组件状态。配置在统一 Settings 入口验证。
- Celery 是独立进程，复用配置但不导入 Web app 或创建 Web 客户端；无业务副作用的 smoke 任务仅返回已知值。迁移由明确一次性命令执行，不放入服务启动。
- Alembic 只建最小空基线链，不提前创建业务表。Compose 组合进程，不拥有业务状态；外部地址可替换，凭据只给后端/Worker。
- 测试和验收拥有自己的项目、数据库、桶、随机端口及缓存；清理只针对当前任务资源。实际运行入口与 CI 复用同一命令，远端 Actions 未触发时明确标为未运行。

## 实施顺序

1. 后端：固定依赖与锁文件，Settings、连接层、health/ready、错误与脱敏请求日志、迁移链、Celery app 与 smoke。补成功、失败、超时、配置和资源关闭的测试。
2. 前端：Next.js/React/TypeScript，服务端转发与响应校验，简洁且可访问的状态页，加载/失败/恢复与手动重试；补代理与 UI 行为测试，Dockerfile 与生产构建。
3. 集成：Compose 明确 migrate/test 服务及 Worker 健康；补统一整栈验证入口、前后端 CI、迁移重复执行与 Worker 真实任务检查。
4. 验收：本机执行 CI 等效检查和生产镜像构建；干净隔离项目启动、迁移、ready、对象存储和任务结果；真实浏览器检查正常、依赖故障、API 断开、恢复和窄屏。
5. 交付：复查依赖、状态与退出清理，更新 README/RUNBOOK/HANDOFF/任务卡；固定候选提交并按队列快进合入 master，不推送；清理任务缓存、构建资源与无人依赖的 worktree。

## 风险与门槛

- Python/Node 和框架版本需核对官方来源并锁定；本机无可用 Python 时使用 Docker 内一致的 uv/Python 环境。
- 测试成功不能代替浏览器验证；依赖层历史通过不能代替本轮整栈通过。
- 任一验收失败先定位再修复；不通过空测试、静默跳过、占位响应或日志泄密获取绿色结果。
