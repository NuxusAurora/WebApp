# 学习目标与 AI 难度策略

2026-11-08 用户要求：学习目标改为“及格就好 / 多学一点 / 大师之境”，让 AI 根据选项确定不同学习难度。此计划纳入后续 AI 开发；本轮只实现 Phase 1 选项及保存，不宣称已有 AI 教学能力。

## 产品约定

| 目标 | 后续规范值 | 讲解和例题 | 练习方向 |
| --- | --- | --- | --- |
| 及格就好 | pass | 核心概念、必要先修、基础公式与典型例题，解释分步且直接 | 基础达标、单知识点与常见题型，优先修复基础错误 |
| 多学一点 | expand | 系统理解原理、解释原因，覆盖常见变化和实际应用 | 标准题及变式，适量知识点组合与迁移应用 |
| 大师之境 | mastery | 深入推导、边界条件、不同解法、知识间联系与高阶拓展 | 综合题、证明和开放问题，逐步增加独立推理要求 |

新课程默认“多学一点”。难度是教学策略，不是结果保证；“大师之境”不承诺用户已达到专家水平。AI 还必须结合当前知识点、先修掌握情况与用户表现决定当次难度，不能因选择高目标而跳过必要基础。

## 当前 Phase 1 实现

- 课程新建/编辑的学习目标使用三档选择；通过现有 learning_goal 字符串字段保存中文标签，保持当前 API 和数据库兼容。
- 已有自定义文本不自动猜测档位、不丢弃；编辑时允许保留原有目标，主动选档后才替换。新建和旧目标兼容均有回归测试。
- 课程详情显示实际保存的选择及简短说明。当前不会发送模型请求，不显示虚构 AI 建议或学习结果。

## 后续实施步骤与解耦约定

1. **规范化课程配置。** 在课程/学习领域新增 learning_level 枚举 pass/expand/mastery；创建和更新由服务端验证。新增迁移只将三种已知中文标签映射为对应枚举，其他旧文本独立保留为 legacy_learning_goal，档位暂为空，不能推断后覆盖。旧档位为空时采用明确标记的 expand 默认策略，界面提示用户选择。数据库迁移可回退，不修改已验收迁移。
2. **定义难度策略。** 学习领域拥有 LearningPolicyResolver：输入为档位、知识点、先修与表现快照；输出为 explanation_depth、example_complexity、exercise_band、scaffolding 和 policy_version。档位标签/规范值的映射是公开契约，服务端是策略权威来源；前端不能直接指定 Prompt、评分结论或内部策略参数。
3. **接入 AI 调用上下文。** Phase 2 先让通用调用契约可承载结构化任务上下文；课程到策略的解析由工作流完成，不能让 Provider Adapter 查询课程表。Gateway 保持协议职责，模型切换不修改学习目标、课程结构或学习状态。
4. **接入教学与练习。** 在 Phase 5/6 的工作流和集中管理的 Prompt 中消费难度策略：讲解、例题、练习及反馈均使用同一份版本化策略。生成结果验证其难度标记、知识点范围和先修；不符合要求时有界重试或明确失败，不把模型文字直接写为学习状态。
5. **切换和追溯。** 用户切换目标后，从下一次教学请求生效；记录当次档位和策略版本快照，保留已有会话、练习和评估，不静默重算历史。必要时提示新策略与旧练习的区别。掌握确认仍遵守用户明确确认与既有状态规则。

## 验收门禁

- 同一知识点与相同上下文，三档在讲解深度、例题复杂度、提示量和练习覆盖上有可评审的差异；用真实样例评审，不仅检查 Prompt 字符串。
- 高目标遇到未掌握先修时先补基础，低目标不降低事实准确性与必要先修要求；难度策略不授予自动确认掌握或绕过用户隔离的权限。
- 切换档位、切换模型、刷新后选择均保持正确；旧自定义目标和历史练习完整保留。
- 策略解析可独立测试，Provider 替换不改课程 UI；取消、超时和 Schema 失败不得修改学习状态。记录实际已测与未测内容。

## 状态

Phase 1 选项：已实现，保存与刷新恢复已验收；规范化枚举迁移、LearningPolicyResolver、Prompt、AI 调用和三档教学效果：待后续阶段，尚未实现或验收。
