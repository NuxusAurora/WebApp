# Phase 4 首条闭环：小节知识点

范围：已确认目录 → 按小节生成知识草稿 → 编辑/核对差异 → 显式确认。仅主代理；不推送、不部署云端/Sites。依赖分析、图谱、学习会话与掌握状态变更留后续。

## 解耦约定

- knowledge 拥有知识内容、草稿和确认；复用既有 StructureVersion/StructureEvent/WorkflowRun 存储，新增 section_id 范围及类型过滤，目录查询不得消费知识版本。正式知识点只在课程行锁内确认；revision、base_course_revision 保护跨小节并发，重复确认幂等。
- 路由组合所有权、课程、小节和 Gateway；模型只返回受 Schema 约束的建议，不能修改数据库或学习状态。网络期间不持有课程锁，返回时重新验证小节有效性与课程基线；失败/取消保存工作流状态且保留旧草稿。
- 原目录服务只经知识领域的明确服务函数查询受影响节点、执行归档；知识服务依赖目录模型与共享版本记录，不反向依赖目录服务/路由。移除小节必须列明并确认其知识点归档，旧版本/ID/学习状态不删除。依赖表尚不存在，不伪造依赖处理。
- 前端 KnowledgeEditor 拥有当前小节草稿/加载/错误/取消，CourseSpace 只组合页签及未保存保护。同源代理白名单新增精确知识端点；不共享目录编辑状态。不确定项清除并保存后才能确认，移除逐项列出。切节/卸载中止、忽略迟到响应。
- 正式 ID 只显式匹配当前小节未归档节点；新节点按 temp_id 映射 UUID；重复/跨小节/跨课程映射拒绝。确认新内容保留既有学习状态，并标记定义改变需复核，不自动变更掌握状态。

## 实施与验收

1. 0005迁移与知识契约/Prompt；服务及API；目录版本范围隔离与知识归档协调。
2. 课程详情知识点页签：选择已确认小节、默认启用模型生成、草稿恢复、内联表单、差异/不确定项/确认、归档复核。
3. 后端真实边界测试、模型协议/失败/取消/版本冲突，前端行为与代理测试、Ruff/类型/生产构建。
4. PostgreSQL迁移/并发/幂等/持久化及浏览器桌面/窄屏/深浅色验收；先核既有目录上传入口。真实模型质量以实际测试为准，fixture不等同真实效果。
5. 最终diff解耦审查、文档更新、验证候选、本地合入并更新本机服务，回收本任务资源。

实施与功能/解耦复查结果见HANDOFF的2026-11-09小节知识点节。真实浏览器因控制工具故障未验收；保留现有视觉体系，后续补验后再评价视觉质量。

2026-11-09 后续方向已由用户更新：不要求正文输入，优先自动按小节标题联网核对资料并拆分知识点，逐点学习、节末统一测验；接入顺序以[标题检索与逐点学习计划](title-research-learning.md)为准，完整图谱后置。
